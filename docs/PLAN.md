## Standing rules for every worker

1. **Read `docs/SPEC.md` first** (the product spec) and the sections your task names.
   Read `docs/RESEARCH.md` for the evidence behind any claim you surface to a user.
2. **File ownership is strict.** Touch only the paths listed under YOUR task. If you need a
   change in someone else's path, say so in your final report — do not edit it. This is how
   we avoid merge conflicts across parallel worktrees.
3. **Immutability**: frozen pydantic models, new objects never mutation. Money is
   `decimal.Decimal` with `ROUND_HALF_UP` at 2dp. **A `float` must never reach a money field.**
4. **Many small files.** 200-400 lines typical, 800 hard max. Organise by domain.
5. **Every non-trivial module leaves one runnable check behind** — a `pytest` test that fails
   loudly if the logic breaks. Not coverage theatre; the tests in SPEC section 14 are the model.
6. **Verify before you claim done.** Run the tests, paste the real output in your report. If
   something fails, say so with the output. Never report green without having run it.
7. **Pull live docs before using any library** — Context7 MCP (`resolve-library-id` then
   `query-docs`) or the firecrawl skills or web search. Do not code a library API from memory.
8. **The LLM path is always optional.** `tieout reconcile` must run end-to-end with zero LLM
   calls. See ADR-001.
9. **No secrets in git.** `.env` and `opencode.json` are gitignored and contain live API keys.
   Never commit them, never echo their contents into a file, never paste a key into a doc.
10. **Document as you go, accurately.** Every worker updates or creates the doc named in its
    task. No undocumented behaviour. If you deviate from the spec, write down what and why.
11. Commit with conventional commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`). Push your
    branch. Report the branch name and commit SHAs in your final message.

## Integration protocol

- Each worker pushes its own branch and opens a PR against `main`.
- The orchestrator merges. Workers do not merge each other's work.
- If your branch conflicts with `main`, rebase onto `main` and report; do not resolve a
  conflict in a file you do not own without saying so.
